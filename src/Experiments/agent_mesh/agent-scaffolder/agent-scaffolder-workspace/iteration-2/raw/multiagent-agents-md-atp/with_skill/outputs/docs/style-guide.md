# Documentation style guide

The shared standard the Writer writes to and the Reviewer reviews against. Treat this file as
**read-only** during the review loop: propose changes to the human owner rather than editing it
mid-flight. (Starter rules — expand to fit the project.)

## Voice & structure
- Active voice, second person ("you"), present tense.
- Short sections with descriptive headings; lead with the answer, then the detail.
- One idea per paragraph; prefer lists and tables over dense prose.

## Format
- Markdown, one document per file under `docs/`, kebab-case filenames (`getting-started.md`).
- Fenced code blocks with a language tag; runnable examples where relevant.
- Sentence-case headings; no trailing punctuation in headings.

## Facts & accuracy
- Every factual claim must be verifiable against a cited source. Unverifiable claims are
  `Blocking — needs-source` in review, not approved around.
- Define acronyms on first use.

## Tone
- Helpful and direct; no marketing language in reference docs.
